Una función recursiva resuelve un problema grande pidiéndose ayuda a sí misma con una versión más pequeña del mismo problema, hasta llegar a un caso tan simple que la respuesta es inmediata.

Esta página reúne una investigación documental sobre la recursividad y cuatro laboratorios interactivos: factorial, Fibonacci, Torres de Hanói y fractales. Cada ejemplo puede ejecutarse paso a paso para observar cómo se apilan y resuelven las llamadas.

1

Definición de recursividad

En ciencias de la computación, la recursividad es la técnica en la que un procedimiento se define en términos de sí mismo. Un algoritmo es recursivo cuando, para resolver un problema, se invoca a sí mismo una o más veces con subproblemas estrictamente más pequeños, y combina sus resultados para obtener la solución completa [1], [6].

La idea proviene de las definiciones matemáticas por inducción. El factorial, por ejemplo, se define como 0! = 1 y n! = n · (n−1)!: la segunda regla usa el propio concepto que está definiendo, pero aplicado a un número menor [3].

Para que una definición recursiva sea válida no basta con que se refiera a sí misma: cada llamada debe acercarse a un caso base que se resuelve sin más llamadas. Sin ese caso, la función se invocaría indefinidamente [4].

Recursividad: estrategia de solución en la que un problema se expresa como una o varias instancias más pequeñas del mismo problema, más un caso base que se resuelve directamente.

Procedimientos recursivos y sus aplicaciones

Abelson y Sussman distinguen entre el procedimiento (el texto del programa) y el proceso que genera al ejecutarse. Un procedimiento recursivo puede producir procesos con formas muy distintas, y esa forma determina cuánto tiempo y memoria consume [2]. Los tipos más comunes son:

Recursión lineal (simple)Cada llamada hace como máximo una llamada recursiva. Las llamadas forman una cadena que se resuelve al regresar.Factorial, suma de una lista, búsqueda binaria
Recursión en árbol (múltiple)Cada llamada hace dos o más llamadas. El número de llamadas puede crecer exponencialmente.Fibonacci ingenuo, Torres de Hanói, fractales
Recursión de colaLa llamada recursiva es la última operación. Algunos compiladores la convierten en un ciclo y no consume pila adicional [2].Factorial con acumulador, máximo común divisor de Euclides

Aplicaciones

La recursividad es la forma natural de trabajar con estructuras que se contienen a sí mismas. Entre sus aplicaciones principales están:

  • Recorrido de estructuras jerárquicas: árboles binarios, el sistema de archivos (carpetas dentro de carpetas), el DOM de una página web y documentos JSON o XML.
  • Ordenamiento y búsqueda: merge sort y quicksort dividen el arreglo y se aplican a cada mitad; la búsqueda binaria descarta la mitad del rango en cada llamada [1], [7].
  • Búsqueda con retroceso (backtracking): resolver sudokus, el problema de las ocho reinas o laberintos, probando una opción y regresando si no funciona.
  • Grafos: la búsqueda en profundidad (DFS) visita un nodo y luego, recursivamente, a sus vecinos.
  • Compiladores e intérpretes: las gramáticas de los lenguajes son recursivas (una expresión puede contener otras expresiones), por lo que se analizan con funciones recursivas.
  • Gráficos y modelado de la naturaleza: fractales, árboles, costas y nubes se generan repitiendo una regla a distintas escalas [5].
  • Programación dinámica: se parte de una definición recursiva y se guardan los resultados de subproblemas repetidos para no recalcularlos [1].
3

Características de la recursividad

Todo algoritmo recursivo bien construido comparte estas propiedades [4], [6], [8]:

  1. Caso base. Al menos una entrada se resuelve sin llamadas recursivas. Es la condición de paro.
  2. Caso recursivo. La función se llama a sí misma con una entrada distinta.
  3. Convergencia. Cada llamada recursiva debe acercarse al caso base (por ejemplo, n disminuye en 1 o el arreglo se reduce a la mitad). Si no converge, el programa nunca termina.
  4. Uso de la pila de llamadas. Cada llamada pendiente ocupa un marco en la pila con sus parámetros y variables locales. Si la recursión es demasiado profunda se produce un desbordamiento de pila (stack overflow).
  5. Dos fases. En la fase de ida (descenso) se apilan llamadas; en la fase de regreso (ascenso) se combinan los resultados.
  6. Equivalencia con la iteración. Todo algoritmo recursivo puede reescribirse con ciclos y una pila explícita. La versión recursiva suele ser más clara; la iterativa, a veces más eficiente en memoria [2].
4

Complejidad computacional en algoritmos recursivos

El costo de un algoritmo recursivo se describe con una relación de recurrencia: una ecuación que expresa el tiempo T(n) en función del tiempo de las llamadas más pequeñas [1], [3]. Por ejemplo, para el factorial:

T(n) = T(n − 1) + c, T(1) = c ⇒ T(n) = Θ(n)

Existen tres métodos clásicos para resolver recurrencias [1], [7]:

  • Sustitución: se propone una solución y se demuestra por inducción.
  • Árbol de recursión: se dibuja el árbol de llamadas, se suma el trabajo de cada nivel y luego el de todos los niveles.
  • Teorema maestro: resuelve directamente recurrencias de la forma T(n) = a·T(n/b) + f(n), típicas de divide y vencerás. Para merge sort, T(n) = 2T(n/2) + Θ(n) da Θ(n log n).

La complejidad espacial también importa: la memoria extra que usa la pila es proporcional a la profundidad máxima de la recursión, no al número total de llamadas. Fibonacci ingenuo hace un número exponencial de llamadas, pero su pila nunca pasa de n marcos [2].

5

Factorial

El factorial de un número natural n es el producto de todos los enteros de 1 a n. Su definición recursiva es el ejemplo más sencillo de recursión lineal [4], [6]:

n! = 1 si n ≤ 1; n! = n × (n − 1)! si n > 1

Cada llamada espera el resultado de la siguiente, así que se forma una pila de n llamadas pendientes. Al alcanzar el caso base las multiplicaciones se resuelven de regreso.

function factorial(n) {
  if (n <= 1) return 1;        // caso base
  return n * factorial(n - 1); // caso recursivo
}

Sucesión de Fibonacci

La sucesión de Fibonacci comienza con 0 y 1, y cada término es la suma de los dos anteriores: 0, 1, 1, 2, 3, 5, 8, 13… Su definición recursiva genera una recursión en árbol, porque cada llamada produce dos más [2], [3].

El problema es que los subproblemas se repiten: para calcular F(5) se calcula F(3) dos veces y F(2) tres veces. Por eso el número de llamadas crece como φⁿ. Con memorización (guardar cada resultado la primera vez) el árbol se reduce a una cadena y el costo baja a lineal [1].

function fib(n) {
  if (n < 2) return n;            // casos base
  return fib(n - 1) + fib(n - 2);
}

// Con memorización
function fibMemo(n, memo = {}) {
  if (n in memo) return memo[n];
  if (n < 2) return n;
  return memo[n] = fibMemo(n-1, memo)
                 + fibMemo(n-2, memo);
}

Torres de Hanói

El rompecabezas, propuesto por Édouard Lucas en 1883, consiste en mover una torre de n discos de la varilla A a la C, usando B como auxiliar, sin colocar nunca un disco grande sobre uno pequeño [3].

La solución recursiva tiene tres pasos: mover los n − 1 discos superiores a la varilla auxiliar, mover el disco mayor a su destino y volver a mover los n − 1 discos encima de él. De ahí sale la recurrencia T(n) = 2T(n − 1) + 1, cuya solución es 2ⁿ − 1 movimientos, y se demuestra que no existe una solución más corta [3], [4].

function hanoi(n, origen, destino, auxiliar) {
  if (n === 0) return;               // caso base
  hanoi(n - 1, origen, auxiliar, destino);
  mover(n, origen, destino);
  hanoi(n - 1, auxiliar, destino, origen);
}

Fractales

Un fractal es una figura autosemejante: cada parte se parece a la figura completa. Benoît Mandelbrot acuñó el término en 1975 y mostró que muchas formas naturales, como costas, helechos y ramas, siguen este patrón [5].

Los fractales se dibujan de forma natural con recursión: la función dibuja una pieza y se llama a sí misma para dibujar copias más pequeñas. El parámetro profundidad es el caso base: cuando llega a 0, se dibuja la forma simple y se detiene [4], [6].

  • Árbol fractal: un tronco que se divide en dos ramas más cortas, cada una de las cuales es un árbol.
  • Triángulo de Sierpinski: un triángulo dividido en cuatro; se quita el central y se repite en los otros tres.
  • Copo de nieve de Koch: cada segmento se reemplaza por cuatro segmentos de un tercio de su longitud, con un pico en medio.
function rama(x, y, largo, angulo, prof) {
  if (prof === 0) return;            // caso base
  const x2 = x + largo * Math.cos(angulo);
  const y2 = y - largo * Math.sin(angulo);
  linea(x, y, x2, y2);
  rama(x2, y2, largo * 0.72, angulo + abertura, prof - 1);
  rama(x2, y2, largo * 0.72, angulo - abertura, prof - 1);
}

Conclusión

La recursividad es una de las ideas fundamentales de las ciencias computacionales porque permite describir problemas complejos con pocas líneas que reflejan directamente su estructura. Una vez identificados el caso base y la forma de reducir el problema, la solución se escribe casi igual que su definición matemática, como se vio en el factorial y en las Torres de Hanói.

Los ejemplos de esta página también muestran sus costos. Cada llamada ocupa memoria en la pila, y una recursión en árbol mal planteada, como Fibonacci ingenuo, repite trabajo hasta volverse exponencial. Analizar la recurrencia permite anticipar ese comportamiento y corregirlo con técnicas como la memorización, la recursión de cola o la conversión a programación dinámica.

Más allá de los ejemplos clásicos, la recursividad sostiene algoritmos de ordenamiento, búsqueda en grafos, compiladores, gráficos por computadora y el modelado de formas naturales mediante fractales. Comprenderla, junto con su análisis de complejidad, es indispensable para diseñar algoritmos correctos y eficientes, y para reconocer cuándo conviene una solución iterativa.
